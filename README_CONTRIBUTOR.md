
# 👨‍💻 Инструкция для участника команды (Contributor Guide)

Привет! Данный документ описывает регламент совместной работы над проектом. Пожалуйста, внимательно ознакомьтесь с правилами работы с репозиторием, чтобы избежать конфликтов в коде и сделать процесс разработки максимально удобным для всей команды.

---

## ⚠️ Главное правило

> **Никогда не делайте коммиты напрямую в ветку `main`!**
> 
> Все новые функции, исправления багов и доработки должны реализовываться в **отдельных ветках** и попадать в `main` только после проверки через **Pull Request (PR)**.

---

## 📋 Стандартный рабочий процесс (Git Workflow)

### Шаг 1. Клонирование репозитория (однократно)
Если вы еще не клонировали репозиторий к себе на ПК:
```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd <НАЗВАНИЕ_ПАПКИ_ПРОЕКТА>

```

---

### Шаг 2. Получение актуального кода

Перед началом работы над новой задачей всегда переключайтесь в ветку `main` и подтягивайте свежие изменения от коллег:

```bash
git checkout main
git pull origin main

```

---

### Шаг 3. Создание рабочей ветки

Создайте новую ветку под конкретную задачу. Название ветки должно отражать суть работы:

* Для новых возможностей: `feature/название-фичи` (например, `feature/user-auth`)
* Для исправления ошибок: `fix/описание-бага` (например, `fix/button-style`)
* Для документации: `docs/описание` (например, `docs/update-readme`)

```bash
git checkout -b feature/ваша-фича

```

---

### Шаг 4. Разработка и локальные коммиты

Вносите изменения в код. Старайтесь делать небольшие атомарные коммиты с понятными сообщениями:

```bash
# Проверить статус измененных файлов
git status

# Добавить файлы в индекс
git add .

# Сделать коммит с понятным описанием
git commit -m "Добавлена валидация формы входа"

```

---

### Шаг 5. Отправка ветки на GitHub

Когда задача готова (или часть работы сделана и нужно показать код), отправьте ветку на GitHub:

```bash
git push origin feature/ваша-фича

```

---

### Шаг 6. Создание Pull Request (PR)

1. Перейдите на страницу репозитория на GitHub в браузере.
2. Вверху страницы появится плашка с вашей только что отправленной веткой. Нажмите кнопку **Compare & pull request**.
3. Заполните данные PR:
* **Title (Заголовок):** Кратко опишите, что делает этот код (например: `Реализация авторизации через JWT`).
* **Description (Описание):** Опишите основные изменения, добавленные модули или особенности реализации.


4. Нажмите **Create pull request**.
5. Уведомите тимлида / владельца репозитория о том, что PR готов к проверке (Code Review).

---

### Шаг 7. Доработка по замечаниям (если требуется)

Если владелец проекта или коллеги попросят внести изменения в ходе Code Review:

1. Перейдите в ту же рабочую ветку на локальном ПК (`git checkout feature/ваша-фича`).
2. Внесите необходимые правки.
3. Сделайте `commit` и `push`:
```bash
git add .
git commit -m "Исправлены замечания по ревью"
git push origin feature/ваша-фича

```


4. Pull Request на GitHub **обновится автоматически**, создавать новый PR не нужно!

---

## 🧹 Очистка после слияния (Merge)

После того как ваш Pull Request одобрен и слит в `main`:

1. Переключитесь на ветку `main`:
```bash
git checkout main

```


2. Подтяните обновленный `main` с вашими изменениями:
```bash
git pull origin main

```


3. Удалите старую локальную ветку:
```bash
git branch -d feature/ваша-фича

```



---

## 💡 Полезные советы

* **Коммитьте чаще:** Лучше сделать 5 маленьких понятных коммитов, чем один гигантский с сообщением "fixed everything".
* **Проверяйте код перед отправкой:** Убедитесь, что ваш код собирается, запускается и не ломает существующий функционал.
